# Navo 项目说明

## 一句话

Navo 是面向工业 B2B 团队的账户研究与外联协作工作台：它把分散的账户信息和外部证据，整理成可解释的资格判断、可复核的外联内容，以及有明确负责人的下一步行动。

## 我想解决的问题

工业 B2B 销售不是“生成一封邮件”这么简单。

真正困难的是一连串相互依赖的判断：

- 哪些账户值得投入时间；
- 判断依据来自哪里；
- 哪些内容是事实，哪些只是推断；
- 什么情况下应该继续研究、准备外联或停止；
- 模型生成的内容怎样进入真实工作流；
- 收到回复后，下一步由谁负责；
- 系统出错、重试或重复接收事件时，如何避免产生冲突结果。

因此我没有从聊天框或功能列表出发，而是先定义了一条完整的操作链：

```text
Accounts → Signals / Evidence → Research → Qualification → Contacts
→ Mission / Play → Message / Sequence → Replies → Next Best Action
```

页面、数据结构、执行边界和测试都围绕这条链展开。

## 五个关键判断

### 1. 围绕核心闭环组织产品

Account、Mission、Approval、Inbox 和 Analytics 构成主要工作区。Agents、Tools、provider、token、cost 和基础设施能力放在次级设置区域。

用户可以沿着同一条操作链完成账户判断、任务执行、内容审核、回复处理和结果复盘。

### 2. 事实、推断和决定各自可追溯

外部网页内容先保存为可追溯证据，资格判断引用这些证据，系统建议不覆盖持久化事实，最终外联动作由人工决定。

这套结构让每一个商业判断都能回答三个问题：

1. 信息从哪里来；
2. 谁做出了判断；
3. 哪个结果真正进入了工作流。

### 3. 模型与确定性代码各司其职

模型用于结构化规划、研究摘要、信号提取和文案准备。线性调度、身份、状态转换、幂等、次数限制和后置校验由代码负责。

确定性的流程节点直接由代码执行，使模型调用集中在需要判断和生成的环节。

### 4. 人工审批进入业务流程

外联内容可以编辑、要求修改、批准或拒绝。待审批状态允许操作；决定落库后变成只读记录。系统不会因为“已经生成”就把内容视为可以发送。

审批页将消息、证据和决定并列展示，并完整记录审核结果。

### 5. 数据直接来自当前工作区

Analytics 直接查询当前工作区的账户、资格、审批、回复、会议和来源数据。每个指标都能回到具体对象和业务记录。

同一套数据语义同时用于产品界面、自动化测试和演示验证。

## 真实模型验证

真实模型 smoke test 覆盖从机会发现到后继外联任务的连续执行。为了确保跨任务实体一致，系统采用以下约束：

- fixture 根据当前账户身份生成；
- 持久化 ID、名称和证据优先于模型叙述；
- 保存结果前执行字段归一化和后置校验；
- 回归测试覆盖不一致公司名称和无依据叙述。

最终验证中，根任务和后继任务均以 AI 规划完成，没有 fallback，并产出一个待审核的 DRAFT。

## 如何查看

推荐按下面顺序演示：

1. Account Detail：证据、资格判断、联系人和下一步；
2. Mission Detail：目标如何变成可回放的执行计划；
3. Approval Review：消息如何结合证据进入人工决定；
4. Reply Inbox：回复如何形成下一步行动和负责人；
5. Analytics：当前闭环结果如何被真实记录。
